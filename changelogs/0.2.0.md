# Changelog - Yamada v0.2.0 (by @Akari-my)

## 🚀 Added

### Game System (`game/`)
- **`GameResult`**: Enum to handle match results (`WIN`, `LOSE`, `DRAW`, `SPECTATING`).
- **`GameMode`**: Comprehensive interface to define game mode rules (handling damage, death, quit events, and win conditions).
- **`KitProvider`**: System to create, register, and apply kits (inventory and armor) to players.
- **`CountdownTask`**: Scheduled task to handle pre-game countdowns with automatic title and sound broadcasts.
- **`CountdownManager`**: Global manager to coordinate, start, and stop individual arena countdowns.

### Data Management & Configuration (`arena/`)
- **`ArenaData`**: Data Transfer Object (DTO) for structured arena configuration and serialization.

### Specific Exceptions (`exception/`)
Added new exceptions extending `ArenaException` for cleaner debugging:
- `ArenaNotFoundException`
- `ArenaFullException`
- `ArenaRunningException`
- `InvalidArenaStateException`

---

## 🔄 Changed & Improved

### `Arena`
- Integrated native support for `CountdownManager` and `GameMode`.
- **Auto-Countdown**: The arena now automatically starts the countdown as soon as the minimum player count (`minPlayers`) is reached.
- **Auto-Cancel Countdown**: If a player leaves during the countdown and the count drops below the minimum, the countdown automatically stops.
- **Auto-Win Condition**: Added automatic win checking (`checkWinCondition`) upon player death or disconnect during a match.

### `yPlayer`
- Added complete saving and restoration of **armor inventory** (`savedArmor`).
- Added management for assigned **Kits** (`kit`).
- Added damage dealt tracking (`damageDealt`).
- Introduced the `reset()` method to clear player state at the end of a match.

### `ArenaManager`
- Integrated 1-to-1 relationship with `CountdownManager`.
- Added automatic cleanup of active countdowns during global shutdown.
